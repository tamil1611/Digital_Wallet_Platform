# Database Setup Instructions

## 1. Overview

The Digital Wallet Platform uses PostgreSQL as its relational database and SQLAlchemy as its ORM. Alembic is used to manage database schema migrations.

These instructions explain how to configure PostgreSQL, connect the database to FastAPI, and apply migrations.

## 2. Prerequisites

Install the following:

* Python
* PostgreSQL
* SQLAlchemy
* Alembic
* Project dependencies listed in `requirements.txt`

## 3. Create the PostgreSQL Database

Open PostgreSQL using pgAdmin or the PostgreSQL command-line tool.

Create the database:

```sql
CREATE DATABASE wallet_management_db;
```

Verify that the database has been created successfully.

## 4. Configure Environment Variables

Create a `.env` file in the project root directory.

Example configuration:

```dotenv
DATABASE_URL=postgresql://username:password@localhost:5432/wallet_management_db
SECRET_KEY=replace_with_a_secure_random_secret
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=30
REFRESH_TOKEN_EXPIRE_DAYS=7
```

Replace `username` and `password` with your PostgreSQL credentials.

Ensure that the database URL format matches the database driver configured in the project.

**Security:** Never commit your actual `.env` file or production credentials to GitHub.

## 5. Activate the Virtual Environment

Open PowerShell in the project directory:

```powershell
cd C:\digital_wallet_platform
```

Activate the virtual environment:

```powershell
.\venv\Scripts\Activate.ps1
```

## 6. Install Dependencies

Install the required Python packages:

```powershell
pip install -r requirements.txt
```

Ensure that the PostgreSQL driver specified by the project dependencies is installed.

## 7. Check Alembic Configuration

Verify that `alembic.ini` exists in the project root.

Check that Alembic is configured to load the database URL and SQLAlchemy metadata correctly.

If the project loads the database URL from `.env`, confirm that the Alembic environment configuration reads the same settings.

## 8. Check Migration Status

Display the current database migration revision:

```powershell
alembic current
```

Display the available migration heads:

```powershell
alembic heads
```

Review the output before applying migrations.

## 9. Apply Database Migrations

Run the following command:

```powershell
alembic upgrade head
```

This applies the available migrations and brings the database schema to the latest migration revision.

If a migration fails, inspect the error and database state before attempting further changes.

## 10. Verify Database Tables

Open the database in pgAdmin or connect using `psql`.

To list tables in the current PostgreSQL schema:

```sql
SELECT table_name
FROM information_schema.tables
WHERE table_schema = 'public'
ORDER BY table_name;
```

Verify that the expected tables have been created.

Depending on the implementation, these may include:

* users
* wallets
* transfers
* deposits
* withdrawals
* transaction ledger
* idempotency records
* audit logs
* transaction limits
* notifications

The actual table names depend on the SQLAlchemy models and migrations.

## 11. Run the FastAPI Application

Start the application:

```powershell
uvicorn app.main:app --reload
```

Open Swagger UI:

http://127.0.0.1:8000/docs

Use the API endpoints to verify that the application can access the database.

## 12. Troubleshooting

### Database Connection Error

Check:

* PostgreSQL is running.
* The database exists.
* The database username and password are correct.
* The database URL in `.env` is correct.
* The PostgreSQL driver is installed.

### Migration Error

Check:

* Alembic configuration.
* Database connection settings.
* Migration revision dependencies.
* Existing database schema and migration history.

Avoid deleting migration files or dropping tables to resolve errors without first checking the consequences.

### Missing Tables

Run:

```powershell
alembic current
```

Then review the migration history and apply the required migrations if appropriate.

## 13. Important Notes

* Keep database credentials private.
* Back up important data before schema changes.
* Review autogenerated migrations before applying them.
* Do not use development credentials in production.
* Ensure that financial transactions use appropriate database transactions and integrity constraints.
